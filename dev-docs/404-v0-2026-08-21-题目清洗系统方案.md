# 题目清洗系统方案（已废弃 → 改为取消泄漏检测）

> **创建日期**：2026-08-21
> **状态**：**已废弃**——调查发现原始数据本身就包含答案，不是提取bug，清洗不可行。改为取消泄漏检测，639题已重新入队。
> **原目标**：用AI清洗答案泄漏的题目——从包含答案的problem_text中提取出纯净的题目和答案。
> **背景**：tier=1中有639题被标记为答案泄漏（451题answer_leak_in_input + 188题answer_leak）。

---

## 1. 调查结论（推翻了原方案的前提）

### 1.1 原始数据本身就包含答案

对原始parquet文件逐题追踪后发现：**数据库的problem_text = parquet的question字段，提取逻辑没有bug**。原始数据集的question字段本身就包含答案值。

| 数据集 | 泄漏题数 | parquet中的question字段 | 原因 |
|---|---|---|---|
| deepmath_103k | 242 | question本身就包含答案值 | 题目说"验证2875这个数字"，2875既是答案也是题目的一部分 |
| oda_math_460k | 188 | question本身就包含expected_answer | question末尾就是答案表达式 |
| polymath | 22 | question正常 | solution以复述题目开头被误判 |
| formal_conjectures | 139 | Lean代码（answer=None） | Lean定理陈述本身包含猜想结论，AI运行中误判 |
| omni_math2 | 2 | question包含答案 | 同deepmath |
| anti_guessing | 1 | solution检测误判 | — |

### 1.2 为什么AI清洗不可行

- **deepmath/oda_math（430题）**：题目本身就包含答案（如"验证2875"），去掉答案会破坏题意
- **polymath/formal_conjectures（161题）**：题目本身没有问题，是检测逻辑误判
- **从源头修复提取逻辑也不可行**：parquet的question字段就是这样的，提取逻辑是直接复制

### 1.3 检测逻辑的问题

runner.py的泄漏检测有两个问题：
1. **answer检测**：answer值出现在problem_text中就判定为泄漏——但原始数据本身就包含答案
2. **solution检测**：solution前100字符出现在problem_text中就判定为泄漏——但正常解答以复述题目开头

collector.py的answer_leak检测：
- 检测AI输出的"ANSWER LEAK DETECTED"标记——但AI检测到"泄漏"是因为题目固有包含答案

---

## 2. 最终决策：取消泄漏检测

### 2.1 修改的代码

| 文件 | 修改 | 说明 |
|---|---|---|
| `runner.py` 第267-302行 | 删除answer和solution泄漏检测 | 不再阻止题目进入解题系统 |
| `collector.py` 第353-357行 | 删除ANSWER LEAK DETECTED检测 | AI输出此标记后继续运行，由后续判定决定终态 |
| `collector.py` 第830-833行 | 删除answer_leak的completed处理 | 不再有answer_leak终态 |

### 2.2 重新入队

639题已通过 `reenqueue_leak_problems.py` 重新入队到Redis `math:pending`：
- 451题 answer_leak_in_input
- 188题 answer_leak
- extraction_status更新为pending

### 2.3 影响评估

取消检测后，AI在解题时会看到题目中包含的答案。这是可接受的：
- AI可能利用题目中的答案来构建证明（如"验证2875"题，AI知道目标是2875）
- 这不算是"作弊"——题目本身就告诉了答案，AI只需要证明它
- 对于formal_conjectures，Lean定理陈述包含结论是正常的——AI需要证明这个定理
