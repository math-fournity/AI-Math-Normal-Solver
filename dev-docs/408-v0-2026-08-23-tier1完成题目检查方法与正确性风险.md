## 1. 调查背景

### 1.1 用户的怀疑

用户问："我们对我们已经完成的题目，有所怀疑，我们如何确定这些题目真的是完成的，题目完成的检查方法是怎样的？"

2. 这个判定方法能保证 proof 的数学正确性吗？

## 2. 当前"完成"的检查方法

系统有**两层检查**，但都不验证 proof 的数学正确性。

### 2.1 第一层：collector.py 运行时判定

**代码位置**：`collector.py` 第211-277行 `has_real_proof()` 函数 + 第365-375行 `classify_termination()` 中的调用。

判定 `candidate_solved` 需要同时满足以下条件：

#### 条件1：pane 中有 AI 输出的 "PROOF COMPLETE" 或 "证明完成" 标记

```python
PROOF_COMPLETE_MARKERS = ["PROOF COMPLETE", "证明完成"]  # 英文+中文
```

`find_ai_proof_marker()` 函数（第56-105行）负责区分"提示词中出现的 PROOF COMPLETE"和"AI真正输出的 PROOF COMPLETE"：

- **提示词模式**：`"❭ 请按AGENTS.md中的题目直接解答...结尾输出 ### PROOF COMPLETE"`——提示词上下文中含"结尾输出"、"请按AGENTS"、"Pro ·"等模式，被排除
- **AI输出模式**：在 reasoning/proof 末尾，通常以 `### PROOF COMPLETE` 单独成行

#### 条件2：proof 内容 ≥ 100 字符

`extract_proof_content()` 函数（第232-247行）从 pane 文本中提取 proof 内容：
- 过滤掉纯标记行（PROOF COMPLETE 本身）
- 过滤掉 TUI UI 行（"Thinking ·"、"esc twice to interrupt"、"Guide Devin while it works"、"GLM-5.2 High"、"Press opt+t to cycle thinking levels"、"Yapping ·"、"Pro ·"、"lines truncated" 等）
- 检查 marker 之前和之后的内容，取更长的一侧；如果单侧不够100字符，合并两侧

```python
if len(proof_content) < 100:
    return False  # proof内容过短
```

#### 条件3：proof 内容中至少有 2 个数学推理标记

从以下列表中匹配（中英文都覆盖）：

```python
math_indicators = [
    # 英文
    "\\frac", "\\sum", "\\int", "\\Rightarrow", "therefore", "hence", "thus",
    "prove", "proof", "since", "let", "assume", "suppose", "consider", "we have",
    "minimize", "maximize", "constraint", "feasible", "denote", "define", "lemma",
    "$\\blacksquare", "\\blacksquare", "QED", "q.e.d",
    # 中文数学推理标记
    "因此", "故", "由", "设", "令", "假设", "考虑", "可得",
    "方程", "边界条件", "初始条件", "解", "满足", "代入",
    "控制方程", "建立模型", "边值问题"
]
math_count = sum(1 for ind in math_indicators if ind in proof_content.lower())
if math_count >= 2:
    return True
```

#### 附加检查：无工具调用

`check_tool_use()` 函数检查 trajectory 中是否有工具调用。如果有 proof 但检测到工具调用，则判为 `invalid_tool_use` 而非 `candidate_solved`。

#### 完整判定流程

```
pane文本 → find_ai_proof_marker() → 找到AI输出的PROOF COMPLETE标记？
  ├─ 否 → return False（不是candidate_solved）
  └─ 是 → extract_proof_content() → 过滤TUI UI元素
           → proof内容 ≥ 100字符？
             ├─ 否 → return False
             └─ 是 → 匹配数学推理标记 ≥ 2个？
                     ├─ 否 → return False
                     └─ 是 → check_tool_use() → 有工具调用？
                             ├─ 是 → invalid_tool_use
                             └─ 否 → candidate_solved ✅
```

### 2.2 第二层：check_tier1_completion.py 事后检查

判定 `completed` 级别需要：

1. DB last run status = `candidate_solved`（第一层已通过）
2. 硬盘文件完整：
   - `session_info.json` 存在
   - `exports/conversation.json` 存在（含 thinking 数据）
   - `collector/pane_snapshot.txt` 存在（含终态快照）
   - `tmux/tmux_pipe.log` 存在（含完整 TUI 输出）

**这一层只检查数据完整性（文件是否存在），不检查 proof 内容。**

## 3. 关键缺陷：不验证 proof 的数学正确性

### 3.1 当前检查方法验证了什么

| 检查项 | 验证内容 | 能保证什么 |
|---|---|---|
| PROOF COMPLETE 标记 | AI 声称完成了 | AI 输出了完成标记（不是没输出） |
| proof 内容 ≥ 100 字符 | 有足够长的内容 | 不是空 proof 或极短 proof |
| 数学推理标记 ≥ 2 个 | 内容看起来像数学 | 不是纯文字或无关内容 |
| 无工具调用 | 没用外部工具 | proof 是 AI 自己产出的 |
| 硬盘文件完整 | 数据留存完整 | 可以事后审计 |

### 3.2 当前检查方法没验证什么

| 未检查项 | 风险 |
|---|---|
| **proof 的数学逻辑是否正确** | AI 可能输出一个逻辑错误的证明，但格式正确 |
| **proof 的结论是否与标准答案一致** | AI 可能证明了一个错误的结论 |
| **proof 是否完整** | AI 可能输出一个不完整的证明但超过100字符 |
| **proof 是否与题目相关** | AI 可能输出无关的数学内容但包含足够的数学标记 |
| **proof 是否真正证明了题目** | "PROOF COMPLETE" 只是 AI 的自我声明，不是客观验证 |

### 3.3 具体风险场景

1. **错误证明但格式正确**：AI 在推理过程中犯了数学错误（如计算错误、逻辑跳跃、错误的引理引用），但最终输出了 `### PROOF COMPLETE` + 包含数学符号的100+字符内容。当前系统会判定为 `candidate_solved`。

2. **不完整证明但超过100字符**：AI 证明了部分内容后认为完成了（如只证明了充分性没证明必要性），输出 PROOF COMPLETE。proof 内容超过100字符且有数学标记，当前系统会判定为 `candidate_solved`。

3. **无关数学内容**：AI 在 thinking 中讨论了大量数学内容，然后输出 PROOF COMPLETE。pane 中包含了足够的数学标记（来自 thinking 的残留显示），但实际 proof 部分可能是空的或错误的。

4. **AI 的自我欺骗**：AI 可能在推理过程中"认为自己证明了"，但实际上证明有漏洞。当前系统信任 AI 的 "PROOF COMPLETE" 声明，不做独立验证。

## 4. 影响评估

### 4.1 受影响的题数

当前 tier=1 完成度分布：

| 级别 | 数量 | 是否受影响 |
|---|---|---|
| completed | 29,150 | **是**——这些题的 proof 未经验证数学正确性 |
| solved_missing_data | 23 | 是——同上，且文件还缺 |
| 其他级别 | 10,658 | 否——这些题没有被判定为完成 |

**29,150 题（加23题 solved_missing_data = 29,173 题）的 proof 正确性是未知的。**

### 4.2 无法直接量化的错误率

当前系统没有验证 proof 正确性的机制，因此无法直接知道 29,173 题中有多少是错误证明。需要通过抽样验证或其他方法估算。

## 5. 可能的验证方向

### 5.1 对比标准答案

题库 `problem_extraction_progress` 中有 `answer` 字段。对于有标准答案的题，可以对比 AI proof 的结论是否与标准答案一致。

- **优点**：自动化、可大规模执行
- **局限**：
  - 不是所有题都有 `answer` 字段
  - proof 的结论可能以不同形式表达（如 `\frac{1}{2}` vs `0.5`）
  - 结论正确不等于证明过程正确（AI 可能用错误的方法得到正确的答案）
  - 证明题（如"证明XXX"）可能没有标准答案

### 5.2 抽样人工验证

从 29,173 题中抽样 N 题，人工检查 proof 的数学正确性，估算错误率。

- **优点**：最可靠
- **局限**：耗时，样本量有限

### 5.3 AI 审核验证

用另一个 AI（或同一个 AI 的新 session）审核 proof 的数学正确性。

- **优点**：可大规模执行
- **局限**：审核 AI 本身也可能犯错，需要设计好的审核提示词

### 5.4 形式化验证

将 proof 转换为形式化语言（如 Lean/Coq），用机器验证。

- **优点**：最严格
- **局限**：技术难度高，不是所有 proof 都能转换
